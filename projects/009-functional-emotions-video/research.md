数据流：歌曲分析 → 时间与节拍数据 → 分镜和场景函数 → Canvas2D 底画/光层 → WebGL2 笔触与合成 → 浏览器或逐帧捕获 → FFmpeg。

笔触从底画采样颜色，根据局部亮度梯度确定方向，在平坦区域混入噪声流场。变化由时间和固定种子决定。同一环境可重复定位；跨浏览器和 GPU 的像素一致性未验证。

## 实验 A：完整原项目静帧

本机 Chrome 使用 Direct3D11 渲染 30、55、83、120、170、220、290、350 秒，得到八张 1920×1080 JPEG，位于 assets/frames/。

原项目注册 168 个镜头。八帧没有 JavaScript 错误；30 秒画面在绘制其他时间后再次捕获，JPEG 字节一致。详见 [原始验证结果](assets/source-render-verification.json)。

captureMs 包含渲染、GPU 读回与 JPEG 编码，不能直接解释为实时帧率。没有下载歌曲，未验证完整音频播放与整片 MP4 导出。

| 推开光门 | 243.40–245.88 秒 | 剪影、背光与闪光转场 |

四段精选保留作为笔触实验。完整模式引入章节 I–VIII，共 168 个镜头、372.7 秒，按时间顺序播放并支持章节定位。无音频时按实际经过的时间定位场景，画面更新最多每秒 20 次。默认暂停，离开显示区域或切换窗口时暂停。拖动和参数调节触发重绘；笔触参数不改变人物动作。

保留原数字音频特征；词时间查询与口型标记转换为数字标识对应的时间点，LYRICS 为空，无歌词句子。WebGL2 初始化失败时保留截图与说明，并报告失败。

主按钮“播放原版 MV”直接联网读取固定上游提交的 MP3，以 audio.currentTime 驱动画面；暂停、章节定位、拖动和重播同步控制声音。初始状态不请求音频，点击后才加载。静音观看可移除音频；本地文件通过 Object URL 读取，不上传、不持久化。其他音频只伴随播放，未重新提取特征或生成新动作。网页另提供作者有声成片链接。

## 实验 E：原创音乐与新场景适配

本次将讨论落为实际作品《光种的旅行》。输入为原创乐谱和“光种从夜湖生长成光树”的故事要求；本次助手编写乐谱合成与六镜头场景代码，复用上游 paint.js。不是播放上游章节换配乐。

- 音乐：32 秒、90 BPM、D 小调、48 拍、12 小节；钟琴、和声、低音及轻打击乐。Node.js 标准库合成立体声 WAV，固定噪声种子与乐谱可重复构建。
- 分镜：每八拍切镜，依次为夜湖来信、光种落水、水下聚光、破土抽芽、树冠盛放、把光还给夜空。
- 同步：拍点闪光、涟漪、枝条生长和开花按乐谱编排；音频 currentTime 为播放主时钟。知道乐谱的拍点，无需重新提取音频节拍。
- 编辑：底画/油画、暖金/青绿保留同一场景与时间轴，展示渲染器和代码参数的复用。
- 输出：实时 MV、原创 WAV、乐谱 JSON、六镜头截图；可选本地逐帧导出 720p MP4。

实际素材见 assets/demo/；验证见 assets/journey-verification.json。这是一次已完成的 AI 编程制作结果，没有在网页调用 Opus 或音乐生成模型，也没有实现任意音乐自动成片。

## 上游创作方法与成熟度边界

## 2026-10-12：共同理解、创作自由与总览

本次讨论区分两种阶段：制作阶段由模型设计并编写动画代码；播放阶段程序执行这些代码，按音乐时间逐帧绘制画面。画风、节奏与叙事并非一次入口描述随机完成，原作者记录了方向纠偏、参考章节、统一指南、分章实现与联系表反馈。

Skill 可以组织画风、大方向、制作步骤与评审方法；上游实际文件是 STORYBOARD.md 与 ANIMATION_GUIDE.md，不能表述为网页已经接入在线 Skill。用户希望只给审美和大方向，具体角色、意象、故事、分镜及技术方案由模型自主决定。此前固定光种故事、镜头表和参数的提示词是我们补充的具体示例，不是原库对所有创作入口的硬性要求。

创作自由与成品重复性是两个层次：模型先作出创作选择，写入代码后，时间函数与固定随机规则保证同环境重复定位。提示词不保证不同模型产出相同代码。音乐提供节拍、强弱、段落或词时间依据，模型需设计动作、切镜和灯光关系，再查看实际声画并调整。我们的原创音乐与动画是根据共同乐谱编写，未实现上传现成音乐后自动分析并成片。

网页新增一张能力、效果、原理、价值与场景总览，使用原库和原创演示实际帧作为插图，由 imagegen 编排；原始帧保持保留。总览图为信息图，不是网页实际截图。另提供不依赖原库的独立创作提示词。扩展业务方向仍标注为建议，新题材需要新内容及音乐适配。

## 发布整理：模块与产品路线

网页和根摘要共同覆盖定位、效果、能力、模块、原理、创作约束、价值、场景扩展与验证边界。引导图沿用已生成的同一张 PNG，移动到开篇，作为索引预览；没有重新生成或修改图片。

七个模块分别承担：音乐信息分析、故事与创作组织、人物及章节绘图、动作时间轴、油画引擎、播放体验、导出与评审。渲染器和时间轴可复用，新音乐的分析、故事、场景及声画对应需要重新制作。网页明确区分原库制作环节、本研究新增交互以及待建设产品能力。

最直接的产品方向是音乐定制 MV。进一步可用 Skill 固化风格和评审流程，以模型自由构思和写码、预览反馈及重渲染形成迭代，再加入音乐上传、模型服务、渲染队列、版本保存、素材管理与系列模板。这是扩展路线，当前没有实现平台服务。音乐输入可以是自有作品、授权曲目或另行生成的音乐；生成音乐不是这个原库的核心。
