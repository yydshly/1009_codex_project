从单曲定制，扩展到音乐分析、模型分镜与写码、自动检查、批量导出和系列模板。当前已完成代码作品与一次原创适配，自动上传成片平台仍待建设。

创作方法 / 方向明确，细节由模型发挥

Skill 控制方向，代码实现画面

用户提出审美和大的创作方向，模型自主决定具体故事、角色、意象和分镜。它在制作中建立必要规范，并把选择写进可运行的动画代码。

01 / 创作约束

风格与大方向交给 Skill

Skill 可以沉淀画风、创作目标、制作步骤与评审方法。原库实际使用 STORYBOARD.md 和 ANIMATION_GUIDE.md；这里将这套方法理解为可复用的 Skill，而非网页已接入的在线功能。

02 / 模型自由

故事与分镜由模型设计

不需要用户逐镜指定位置、颜色数值和动作。模型在整体方向内自由构思，再自行制定分镜、角色画法和一致性规则。我们此前固定光种故事的提示词，是具体示例。

03 / 绘图实现

形状 → 笔触 → 动态画面

线条、曲线、椭圆和渐变先组成底图；笔触从底图取色、沿边缘或流场排列。对象位置、形状、镜头和笔触随时间变化，连续帧形成动画。

04 / 音乐适配

把节奏变成动作依据

节拍、强弱、段落和歌词时间可用于安排切镜、动作、灯光与情绪推进。模型需设计这些对应关系；查看实际声画效果后再调整时间轴和代码。

05 / 成品复现

创作自由，执行可重复

创作时可以自由选择；选择写入代码后，同一环境、时间和参数能重新绘制相同画面。提示词提供方向，确定性来自实现后的时间函数与固定随机规则。

06 / 表现范围

抽象感来自画法与笔刷

大笔触与简化轮廓会弱化细节，适合诗意、梦境和寓言表达。模型也可编写更具象的场景；精细人脸、复杂表演或三维空间需要补充相应绘制与渲染能力。

能力拆解 / 从音乐到可播放作品

七个模块，组成完整制作链路

原库是一支 MV 的源码工程，也包含可复用的渲染与制作方法。把模块拆开，才能分清哪些直接复用、哪些需要模型为新音乐重新创作。

01 / 音乐信息

节拍、能量与词时间

原作使用 librosa、Demucs、Whisper 与歌词对齐生成数字特征。它们回答何时有重拍、音量变化、段落和词句，为切镜与动作提供依据。

新歌曲需重新分析；本次原创演示直接使用共同乐谱和拍点。
02 / 创作组织

故事分镜与 Skill 方法

STORYBOARD.md 写故事与镜头，ANIMATION_GUIDE.md 统一人物、画风、接口与评审。模型在大方向内决定细节，规范支撑多章节的一致性。

可沉淀为 Skill；原库使用创作文件，网页没有在线模型调用。
03 / 画面内容

角色、场景与章节代码

cast.js 提供可复用角色和道具；ch/c1…c8.js 定义每个镜头的底画、光层与动作。几何图形、曲线、渐变和粒子构成画面。

新故事通常重写场景与动作；系列作品可共享人物与视觉元素。
04 / 动作编排

时间轴、镜头与确定性

lib.js 组织镜头、缓动、相机与角色动作。画面按歌曲时间计算，固定随机规则让同一时间可重复绘制，便于定位、修改和导出。

更换伴奏只会伴随播放；音乐对应关系需要重新编排。
05 / 画风引擎

Canvas2D → WebGL2 笔触

paint.js 从底画和灯光取色，按边缘／流场排列约六万个多尺度笔触，再加入发光、颗粒、织纹和暗角，形成运动的油画质感。

已在原作和新光树场景复用；其他画风需要修改或替换渲染处理。
06 / 观看体验

有声播放与参数实验

main.js 组合原版章节；本研究页增加原曲联网播放、章节跳转、静音／本地音频和原创播放器，支持笔触、配色及底画对比。

播放执行已完成的代码，实时画面需要浏览器支持 WebGL2。

逐帧导出与画面评审

联系表检查镜头首、中、末帧；逐帧捕获再与音轨合成为视频。检查轮廓、节奏、转场和性能后修改代码，形成优化循环。

03 / 原理

先画清楚，再画成油画

歌曲提供时间与节奏，场景代码决定看见什么，渲染器决定它呈现什么质感。

01

分析音乐

提取节拍和音频能量；分离人声、识别词时间，再与歌词对齐。

02

绘制两层底画

Canvas2D 绘制场景轮廓与颜色，另一层绘制灯光、火焰和光晕。

03

GPU 笔触重绘

约六万个笔触从底画取色。边缘处顺着轮廓，平坦处跟随流场。

04

合成与输出

叠加发光、织纹与颗粒，得到可播放、可逐帧捕获的连续画面。

确定性时间轴

画面 = f（歌曲时间）

跳到同一时间，就能重新得到对应画面。动画无需从上一帧积累状态，方便定位修改，也方便分工渲染。
