一个关于「最终作品如何形成」的研究

把 3D 素材，
编排成体验。

Dioramas 将素材流水线、共享实时引擎与 20 个网页案例连接起来。外部模型生产素材，设计与代码定义画面、行为和内容。我们研究的是：同一份素材，如何被持续设计与控制，形成完整网页。

01 / OUR UNDERSTANDING

从 AI 素材，到可交互网页。

沿用我们的原图

我们的理解是：调用生图与图转 3D 模型生产素材，处理成网页可用资产，再通过设计、共享引擎、场景代码和 HTML 内容，形成最终的网页效果。这里的“生成”分为模型生成素材与浏览器计算画面；两者发生在不同阶段。

作品如何形成

设计目标 + 可用素材 + 共享引擎 + 场景代码 + HTML 内容 + 测试迭代

01 / 模型的贡献

提供形状与视觉素材

生图模型提供参考图、背景或产品图片；图转 3D 服务提供几何与 PBR 贴图。部分角色资产还可带骨骼或动画。生成能力来自外部服务，模型并不包含完整的网页设计与交互规则。

02 / 本库的贡献

调度、处理、编排与实现

开发脚本组织生成任务、参数、结果记录与素材优化；共享代码管理渲染和输入；案例代码实现专属效果。模型接入后的材质调整、镜头、灯光、状态和内容关联，都有具体工程工作。

03 / 设计的贡献

决定最终作品如何表达

对象放在哪里、用什么灯光、滚动时看哪里、点击后发生什么、文字怎样排布，需要设计并落实到代码。生成任务脚本的输出是素材；优秀的页面由构图、叙事、内容和迭代共同形成。

04 / 运行的方式

浏览器持续计算画面

成品加载已有资产，用户输入改变场景状态，程序逐帧更新镜头、物体与效果参数，WebGL / GPU 绘制画面，HTML 同步说明与界面。普通浏览、滚动和点击通常无需再调用生成模型。

可迁移价值

素材生产流水线、渲染底座、输入与滚动、状态控制、特效实现、完整页面案例和开发工具，都可按需求迁移。已有授权 GLB、CAD 导出或程序几何也能接入；特定效果需要抽取案例逻辑、准备合适资产并适配。

SHARED ENGINE / 对“引擎”的理解

把通用代码组织为多个作品的运行底座。

底层的 Three.js / WebGL 提供图形能力，Dioramas 在其上封装共同的运行机制。每个作品继续添加自己的状态、效果和内容。页面的排版、触发条件与行为规则由对应代码定义。

Three.js / WebGL / GPU→共享引擎 src/core/*→场景代码 + HTML / CSS→最终作品

渲染与资源

engine.js：相机、帧循环、尺寸适配、环境光与后期。assets.js：模型 / 贴图加载、进度和表面采样。

输入与滚动

input.js：指针位置、速度、按下状态和平滑值。scroll.js：Lenis、GSAP、章节进度与文字显现。

通用界面

ui.js：加载界面、光标、磁吸按钮与案例导航。具体网页布局和内容仍在各案例中实现。

可选视觉效果

reflector.js：平面反射；volumetric.js：体积光；textures.js：程序纹理。案例按需接入与调参。

例：按住鼠标，让机甲蓄力

指针模块提供按下状态 → 场景代码累计蓄力值 → 更新发光、灯光、粒子与动画 → 引擎绘制新画面。蓄力速度、上限、释放行为和提示文字，属于这个作品的设计与专属代码。

共享模块依据 ENGINE.md 的 Core API。上例是对职责的解释，具体效果以案例实现为准。特殊水波、液体、分解、音频和游戏规则分布在各案例与依赖中。

开发工具：帮助生产素材、优化、截图与检查 +

这些工具主要在开发阶段运行，协助制作与评审网页。浏览器访问成品时主要运行场景和界面代码。

工具做什么产出 / 使用边界
gen.mjs按任务配置调用生图与图转 3D 服务，保存结果；Meshy 任务记录 ID 并轮询。参考图、原始 GLB、manifest；生成算法与费用来自外部服务。
optimize.mjs去重、焊接、可选减面、量化、meshopt 与 WebP 压缩。适合网页传输的模型；压缩结果仍需在目标设备测试。
optimize-all.mjs批量优化模型并按案例整理，跳过已更新的输出。各案例的优化模型目录；更换项目时需调整目录映射。
shot.mjs在指定视口、滚动位置与鼠标 / 点击状态下截图，采集报错和运行信息。状态截图、帧率等证据；用于检查实际可见结果。
review.mjs拍摄多个桌面滚动状态与手机页面，汇总截图、帧率和报错。评审图与运行记录；审美、完整性和交互质量还需要评审。
contact.mjs把多张截图拼成一张联系表，方便比较状态与构图。评审拼图；帮助发现变化和问题。
thumbs.mjs捕获各案例指定画面，输出图库缩略图。当前“已有效果”中的 20 张上游图片来自该截图链路。

工具含上游目录、端口及 Chrome / GPU 参数，迁移时需要适配环境。本次没有执行上游素材生成或下载模型；图示是制作机制的说明。

05 / WHEN TO USE IT

当体验本身，也是内容。

01 / 品牌与产品

让产品成为页面主角

香水、手表、鞋、机械设备的新品介绍。通过镜头与局部互动突出材质、结构和品牌氛围。

02 / 展览与传播

让访客参与故事

线上展览、文物讲解、艺术专题、活动体验。用探索、灯光与章节状态组织叙事。

03 / 设备与培训

把结构变成可探索内容

产品售前与部件认知。需要有结构信息的分件模型，再增加热点、分解动画和内容映射。

适用性判断

重视视觉体验与探索的场景更容易受益。表格后台、快速信息检索和低性能设备优先的业务页面，采用这套重视觉方案前需要权衡加载、易用性与开发成本。

06 / VALUE & TRANSFER

价值在于，素材能被持续设计与控制。

研究判断

它提供了从素材到体验的工程连接，也保留具体作品的实现参考。下面说明可借鉴的价值与成立条件；本次没有验证效率提升、营销转化或所有设备的性能。

01 / 素材与体验解耦

同一资产，可以有不同表达。

更换灯光、镜头、材质、状态与文字，就能形成产品展示、结构讲解或主题叙事。已有授权素材与程序几何也能接入，素材来源有选择空间。

成立条件：资产质量、结构和授权满足场景需求。
02 / 通用机制复用

把重复工程组织起来。

共享资源加载、渲染循环、尺寸适配、后期、输入和滚动，让新作品沿用共同的运行接口。场景与设备参数依然需要单独配置。

成立条件：明确模块接口、版本和性能预算。
03 / 设计能被精确修改

画面与行为由参数和规则定义。

镜头看哪里、何时展开、长按多久、粒子如何变化、内容何时出现，都能在代码中定位和调整。最终质量来自设计判断与持续检查。

成立条件：开发者理解视觉、动画和交互关系。
04 / 空间对象与内容关联

让用户操作产生明确反馈。

将命中的部件或场景状态映射到文字、热点与界面，适合产品探索和结构认知。本地泵实验用部件 ID、展开比例和流向状态验证了这条连接。

成立条件：准确语义、可发现的操作和等效输入。
05 / 开发过程有证据

保留任务记录与实际画面。

生成记录、优化结果、指定状态截图、移动界面与报错信息，帮助追踪素材和发现实现问题。工具采集证据，评审判断作品是否完整、好用和美观。

成立条件：记录版本与环境，针对意见再次验证。
06 / 对我们的复用意义

先迁移控制方法，再扩大资产。

从现有几何开始，保留对象 ID、状态、镜头、说明与清理接口，再替换适合的素材。泵模型已拆成独立工厂与部件说明，可由宿主传入 Three.js。

下一步：用另一份授权资产验证接口与效果适配。
采用建议

先明确用户要看什么、操作什么、获得什么说明；选一份合适素材，完成一个关键交互并实测，再扩展视觉效果。设备参数、数据接入与专业仿真需另外提供；项目的素材与引擎能力不能自动保证这些结果。

08 / NEXT POSSIBILITIES

把一个作品，扩展成可复用系统。

后续方向 · 尚未实现

这些方向需要新增数据、接口或验证工作。下面给出具体下一步与验收标准，帮助区分已有能力和未来设想。

01

授权资产与部件语义

用授权分件 GLB 替换程序几何，记录部件 ID、装配位置、展开方向、热点、来源与许可。整体网格先分件或补充结构资产。

02

SceneConfig 与编辑界面

将模型来源、主题、镜头关键帧、热点内容和触发条件配置化；增加校验、预览和保存，供新产品复用控制层。

验证：修改一份配置生成第二场景，错误配置得到明确提示。
03

特效与交互模块化

从案例提炼水波、粒子、长按蓄力、液体和分解控制，定义输入、更新、尺寸适配与释放接口，并标明依赖和预算。

验证：同一模块运行在两个场景，切换和销毁不遗留资源。
04

专业审核的教学任务

增加识别题、任务状态与学习记录。设备信息由专业人员审核，实际测量数据、仿真结果和维护规则由独立来源提供。

验证：内容审核通过，任务反馈与真实数据来源明确对应。
05

设备分级与替代视图

按需加载、模型 / 贴图分级、后期开关、触摸与键盘操作、减少运动与静态视图，用目标设备实测决定策略。

验证：手机与笔记本达到各自预算，关闭 3D 后主要内容仍可读。
