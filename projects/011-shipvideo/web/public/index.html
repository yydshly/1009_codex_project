COMPLETE UNDERSTANDING / 理解摘要

我们对这个库的完整理解。

按十个主题展开，区分实现、分析与建议。
先看结论，再按主题阅读详细说明与源码依据。

定位
由 Agent 编排、用代码绘图的解释短片制作组件。网址提供信息，模型生成动画程序，浏览器与编码器生成视频；固定实现未使用 Remotion 或 HeyGen。
能力
读取网页文字与元数据、组织 6–10 个叙事节奏段、绘制动态文字/流程/图表/界面示意、检查技术问题并修改、编码 MP4 与签名下载。创作约束不等于事实核验。
模块
Next.js 输入和展示、POST 任务创建与 GET 状态 API、OpenComputer 会话客户端和运行环境、导演 Agent、web_fetch、check_scene/render_video 场景工具、自写 renderer 及会话工作区交付。
原理
创建会话并发送 JOB，Agent 读取资料、写单份 HTML、检查修改；虚拟时钟按帧推进 rAF、定时器和动画，Playwright/Chromium 截图流交给 FFmpeg。控制的是同一份代码的时间状态，模型重新创作仍有变化。
输入
公开 HTTP(S) URL 或不超过 2000 字符的文字简报。抓取不执行页面 JS、不登录、不录制真实操作；当前表单不上传图片、视频或文档。已核实的受众、能力、流程与限制更适合作为简报。
输出与效果
单份 HTML 是中间产物，最终为 1920×1080、H.264、默认 30 fps 的静音 MP4；导演目标 20–40 秒，工具支持 3–90 秒及 24/30 fps。适合文字和图形驱动的解释片，绘制界面不等于真实产品录屏。
业务价值
可能减少重复制作和销售解释成本，服务产品发布、新功能通知等特定内容任务。需要受众、分发渠道和行动入口，以可用成片总成本、有效试用/预约/功能使用验证；未确认获客或收入提升。
对我们的意义
当前直接商业价值有限，仅借鉴“读取信息 → 编排内容 → 写动画代码 → 稳定渲染”的流程，研究已核实资料、结构化叙事、可控画面与逐帧交付，暂未接入上游或总库批量制片。
可扩展方向
结构化简报与中文模板、关键帧视觉评审、用量与返工记录、竖屏、配音音乐与字幕、真实截图/录屏素材、多模型和本地适配、持久队列及预算管理；均需另行开发和验证。
依据与交付
沿用 2026-10-10 的完整原创引导图，PNG/SVG 字节保留；2026-10-12 复核 main 仍为 53d7c6f。记录 Linux arm64/Node.js 22 运行基线及未发现 LICENSE 的事实，交付静态研究网页，未运行付费生成或验证质量、费用、速度与业务收益。

从提交到下载，发生什么？

  1. 输入提交 URL 或不超过 2000 字符的简报，后端检查格式与当前限额。
  2. 创建创建 OpenComputer 会话，等待 runtime.connected，再发送 JOB。
  3. 创作必要时调用 web_fetch；编排节奏、写 HTML，check_scene 后修正。
  4. 渲染按帧推进时间，浏览器截图，经 FFmpeg 编码为 MP4。
  5. 交付复制到工作区；前端查询事件和文件，取得签名 URL 预览与下载。

完整生成依赖模型和运行服务。当前限额与阶段信息不能替代持久队列、预算账本或业务验收；本次部署的是静态研究网页。

目标是让客户预约演示。

模型与运行费用 + 核实、修改、返工的人力 + 配音、尺寸与发布适配。按“达到发布要求的成片”比较，不能只算 AI 起草速度。
