04 / UNDER THE HOOD

一帧画面，是时间的函数

底层不是 Remotion：本研究版本的模板采用 HyperFrames。两者都使用网页技术按帧生成视频，具体编写方式和时间控制接口不同。

DETERMINISTIC MOTION

定位到 8 秒，画面就回到 8 秒

动画读取统一时间，不依赖运行了多久。可以跳帧、重渲染、逐帧比较，也能精确定位转场缺陷。

frame(t) = render(pose(t))

比较同一时刻可见元素的位置与透明度。

GAUNTLET LOOP

制作 → 渲染 → 评审 → 修复

评审者看到成片、需求和参考资料，按时间点检查问题。新的一轮逐项确认修复状态，同时发现新缺陷。

实际输出→独立判断→问题清单↩

06 / WHERE IT FITS

让动作产生一个可见结果

适合卖点明确、流程可视化、文案需要准确修改的短片。以下为基于工作流的适用性判断，不代表已验证的商业转化。

SaaS 与开发工具

输入 → 操作 → 结果。发布功能、解释工作流、制作销售演示。与本地研究总库案例最接近。

04

广告变体与已有视频改进

复用画面结构，调整开头、文字、结尾与比例；用抽帧和评审找出停顿、碰撞和声音问题。

可控修改
采用前应验证哪些限制？

复杂三维和多轮模型评审会增加制作时间；视频素材的真实性、素材授权与业务文案需要单独核实。停滞、响度和颜色数据不能自动证明审美质量，更不能证明广告转化。长剧情与复杂人物表演不属于这套工作流的重点。

07 / REFERENCE VALUE

最值得复用的，是制作方法与质量闭环

以下是我们的研究判断。代码渲染带来可控修改，真正可迁移的经验还包括业务拆解、组件实验、独立判断与可追溯记录。

01 / BUSINESS FIRST

用业务目的约束创意

先明确观众、可证明事实和唯一 CTA，再选择镜头与素材。对我们而言，适合把研究方法、工具流程和服务结果解释清楚。

02 / REPEATABLE OUTPUT

让修改能定位到时间

统一时间控制动作、相机与文字，便于跳帧、替换文案、比较版本和重新输出。本地路径比较验证了 46 项 DOM 状态，未声称逐像素一致。

03 / INDEPENDENT REVIEW

把制作与评审分开

新评审者看真实画面与需求，指出时间点、碰撞与阅读问题；修订后逐项复验。可借鉴到其他程序动画和作品交付。

04 / TRACEABLE WORK

把经验留下来

素材、版本、抽帧、测量、意见与修复记录关联起来。对研究总库而言，一份可追溯的制作台账比只保存最后一个视频更便于复用。

采用判断

优先借鉴 Brief、时间函数、组件实验和评审台账，再按需求适配渲染器与素材工具。字体、浏览器和资产会影响输出；多轮评审与复杂三维仍需投入。测量通过不等于审美达标，制作方法也不等于商业转化。

08 / NEXT EXPERIMENTS

从一次制作，走向可重复生产

以下是我们的扩展设想。它们尚未实现，不能当作上游已经具备的功能。

P1 · 模板化

参数驱动的行业模板

把品牌色、卖点、图片和 CTA 分离为 JSON。固定分镜，批量生成不同产品和广告开头。

验证：修改数据即可生成另一条片，且文字不溢出。
P1 · 工具化

统一渲染与质检入口

封装素材校验、渲染、抽帧、响度检测与评审台账，给每次修改留下版本与证据。

验证：一条命令产出视频、检查结果与可追溯记录。
P2 · 适配

Remotion 与多比例输出

保持策划与评审方法，增加 React 组件适配；为 16:9 与 9:16 分别设计文字安全区。

验证：同一叙事跨渲染器、跨画幅保持可读性。
P2 · 资产

真实三维与证据管理

导入产品 GLB，管理素材授权与业务事实来源，替换手工模型和临时生成素材。

验证：标注跟随模型，产品参数与来源一一对应。
P3 · 协作

按时间点的人工评审

客户直接在关键帧上留修改意见。将“太慢”转换为明确时间段，并关联下一版的修复结果。

验证：评论、版本和修复状态能闭环追踪。
P3 · 效果

连接真实投放数据

比较不同开头、CTA 和画面版本，结合实际播放、点击与后续行动数据评估效果。

验证：使用真实实验数据，区分相关性与因果结论。
