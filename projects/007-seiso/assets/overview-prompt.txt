TITLE:
Seiso 文档规则检查全景图
SUBTITLE:
让反复维护的 Markdown 文档接受统一检查

CORE BOX:
Markdown 类型与元数据 ＋ 文档结构与正文 ＋ 配置规则 → 识别问题 → 输出诊断与有限修复
字段决定如何查，正文与结构决定查什么
kind：文档用途　lang：语言　canonical：权威来源
类型也可按文件路径配置；自定义任意业务字段需另加检查器

SECTION 01:
原理：本地规则与算法，不调用大模型
FLOW, five connected steps:
读取 Markdown 与 seiso.toml
→ 解析标题、段落、表格、链接与位置
→ 解析类型、语言并建立文档索引
→ 运行规则、词表、正则与集合相似度
→ 输出位置、关联来源和修改建议
small notes:
单文件：类型、表达、文件链接、例外
跨文件：标题锚点、重复定义、相似段落
重复检测：标识符或字符片段的 Jaccard 相似度

SECTION 02:
现有能力
GREEN stable box:
默认稳定
• 文档类型缺失或无效
• 本地文件链接目标不存在
• 例外声明无效或已经失效
AMBER preview box:
开启预览
• 当前版本、部署状态等易变快照
• 对话残留、步骤前铺垫和章节混杂
• 重复字段定义、相似段落与归属歧义
• 本地标题锚点缺失、含糊的引用
• 比较性评价附近缺少证据
OUTPUT box:
处理结果
文本 / JSON / SARIF / GitHub 注解
--fix 主要清理确认失效的例外
内容改写由人或外部 AI 决定

SECTION 03:
适合的使用场景
• AI 写文档：编辑后反馈，提交前再检查
• 多人协作：共同执行文档维护规则
• 多文档项目：配置说明集中，其他页面引用
• 操作手册：减少易变状态和含糊指向
• 文档站点：配置路由，检查本地引用
• 工程流程：pre-commit 与 CI 自动检查
SCENE NOTE:
适合反复检查且标准明确的文档；少量随手笔记收益有限

SECTION 04:
对你的 GitHub 研究总库的价值
EXISTING muted row:
已有：projects.json 保存项目元数据
npm run check 校验编号、目录、预览与索引
SEISO VALUE:
• 检查 README、research.md 与 AGENTS.md 的文档问题
• 用类型映射区分入口、参考、操作与决策
• 用领域划分减少不同项目之间的误判
• 让重复说明集中到权威文档，降低多处维护成本
• 把部分检查结果交给 AI，形成修改反馈
• 对“更快、更好”等评价提示补充可核查依据
IMPORTANT NOTE:
固定研究 commit 是复现依据，可按用途保留并填写有理由的例外
Seiso 不替代现有元数据与索引校验
