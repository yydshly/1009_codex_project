02 能力、效果与边界
语音会话 + 6 个工具

      
模型选动作，代码执行动作。
3D 场景和动画提前制作；模型返回工具名称与参数，前端把它们映射到确定的动画或图表。太阳系是演示题材，连接方式可以迁移。

      
输入麦克风音频浏览器采集
连接WebRTC音频 + 事件通道
理解与选择Realtime 模型语音回答 + 工具参数
应用执行前端工具处理函数调用结果回传
呈现Spline / 图表动画、镜头、数据

      

      
语音对话是入口，画面变化是执行结果。
上游包含会话连接、麦克风开关、模型语音播放和事件日志。用户说出需求，模型根据工具定义选择动作并生成参数；前端执行已配置的动画或图表，再把工具结果回传。它展示的是语音、解释与网页行为的联动。
本页保留可操作的 Three.js 示意：文字关键词 → 工具参数 → 镜头、卫星与图表变化。系统朗读仅辅助阅读；真实 Realtime 的意图识别、音质、响应速度、打断表现和多轮效果尚未实测。

      
上游能力与本页展示分别证明什么
项目上游源码实现本页可验证
输入与回答麦克风音频、Realtime 语音输入输出有限文字关键词、固定解说、可选系统朗读
场景效果Spline 预制对象、事件和镜头动画独立 Three.js 太阳系与六类动作示意
数据展示模型传值生成饼图 / 柱状图固定陆海比例 71% / 29%，注明 NASA 来源
外部查询服务器查询 ISS 经纬度并回传模型固定坐标示例，不访问 ISS 接口
证据范围固定提交源码 + 上游自带截图浏览器交互、布局、资源与发布路径检查

      
TECHNICAL DEPTH
有集成价值，算法研究深度有限。
它把现成的语音模型与 3D 场景连接起来。阅读重点是会话、工具协议与事件适配。
语音理解OpenAI Realtime 提供
3D 渲染与动画Spline 提供
本仓库主要实现会话连接、工具定义、动作映射
尚未实现任意场景理解、生成建模、物理模拟

      
边界 / 01
动画范围有限
工具枚举包含金星和天王星，但 README 未列出它们的聚焦动画。可调用名称不等于场景动作已完成。
边界 / 02
图表不会自动校验事实
上游直接使用模型传入的数值。这里采用固定的陆海比例示例；正式教学应接可信数据源。
边界 / 03
ISS 查询与空间定位有缺口
上游查询经纬度供模型播报，画面只触发预设 ISS 动画，没有按坐标更新位置。

      
边界 / 04
成功回报没有确认动画完成
前端先更新场景状态，再默认回传工具成功。它没有读取最终画面或等待动画完成来验证效果。
边界 / 05
只取响应中的首个工具调用
会话处理用 find 取第一个 function_call。复杂指令的多个动作需要另做调用遍历、顺序、取消与失败处理。
边界 / 06
基础能力来自外部组件
没有新语音算法、通用 3D 理解、自动建模或物理模拟。工程价值集中在连接和调度，不能直接推导教学或商业收益。

    


    

      
03 模块与执行原理
固定源码的职责分工

      
动作范围由开发者准备。
工具定义告诉模型“可以做什么”；参数把用户表达变成对象名称；场景适配把名称映射到事件。对象、动画、解释资料与数据源都需要预先配置。

      
7 组模块：连接、协议、呈现和外部数据
模块 / 源码入口职责迁移时要改什么

        
凭据接口app/api/session/route.ts服务端读取 API Key，签发短期 Realtime 凭据；固定提交配置 600 秒有效期。服务器部署、访问控制与额度；600 秒是凭据有效期，不是会话时长。

        
实时会话components/app.tsx麦克风、音频播放、WebRTC / SDP、oai-events、事件处理、连接与释放。断线、错误、麦克风状态、多个调用和真实执行反馈。

        
工具与提示词lib/config.ts · constants.ts角色说明、六个工具、参数枚举、模型与声音配置。领域对象、允许动作、可信解释范围；上游配置不代表当前推荐。

        
场景适配components/scene.tsx加载 Spline 场景，解析参数，用 emitEvent('mouseDown', 对象名) 触发预制动画。对象 ID、镜头和动画；可改成已有 Three.js 场景的操作接口。

        
数据组件lib/components-mapping.tsx · components/charts/按 chart 参数选择饼图 / 柱状图，显示模型传入的数据。数据校验、单位、来源与更新时间，替换领域图表。

        
外部数据接口app/api/iss/route.ts查询 Open Notify 的 ISS 位置，结果由会话模块交给模型。领域接口、超时 / 失败处理；实时位置需另加坐标到场景映射。

        
控制与观察components/controls.tsx · logs.tsx连接按钮、麦克风开关和响应事件日志。用户可理解的状态、纠错入口和可追踪的调用记录。

      

      
一句“看看土星”，经过哪些步骤

      
    
        
  1. 建立连接
    浏览器请求 /api/session；服务器用正式 Key 换取短期凭据。浏览器采集音频，创建 WebRTC 音频轨道和 oai-events 数据通道，用 SDP 完成连接。
    2. 
        
  2. 声明动作范围
    通道打开后发送 session.update，注册提示词与 TOOLS。模型知道可用动作和参数枚举；它不会因此获得所有场景的通用理解。
    3. 
        
  3. 理解用户表达
    语音模型接收音频，给出语音回答或工具调用。工具参数把“土星”转换为 focus_planet 与 planet: Saturn。
    4. 
        
  4. 分发调用
    客户端读取 response.done 中的 function_call，更新 React 状态；参数以 JSON 字符串传给场景适配器。
    5. 
        
  5. 执行预设动作
    场景组件解析参数，触发名为 Saturn 的 Spline mouseDown 事件。图表则进入组件映射；ISS 同时查询服务器接口。
    6. 
        
  6. 回传结果
    客户端用对应 call_id 发送 function_call_output。ISS 与图表调用还触发 response.create，让模型继续回答。上游默认成功信息不等于动画验收。
    7. 
        
  7. 结束与释放
    结束会话时关闭连接和数据通道，停止音频轨道并清空状态。正式扩展还要验证中断、失败与取消后的状态一致性。
    8. 
      

      
这条链路为什么有用
模型处理多种表达方式，应用保留明确的操作范围和渲染逻辑。更换工具、对象映射和资料，就能把同一连接思路迁移到设备、产品或普通网页；迁移收益需要真实任务验证。

    


    

      
04 使用场景与对你的价值
扩展方案，需要新增开发

      

        

        

      

      
对研究的价值
补齐语音交互这一层
Dioramas、Dvor 已提供 3D 画面；这个样例提供把用户表达接到场景操作的方法。
对演示的价值
让提问带动画面变化
讲解对象、视角和图表随问题变化，适合对象清晰、动作有限的教学或展示。
投入判断
先做三个动作就够
优先验证对象聚焦、播放动画、展示可信数据。若目标是研究新算法，可降低本项目优先级。

      
什么时候值得投入，价值怎样验证
你的目标投入判断需要的条件 / 验证
已有 3D 页面，希望能边问边操作工程参考价值较高，可先做小规模接入。明确对象 ID、有限动作、真实任务；对比按钮操作与语音操作的完成率和时间。
理解语音 Agent 如何控制界面适合作为协议与适配入门样例。读会话、工具定义和场景分发；记录请求、参数、执行状态与回答是否一致。
研究语音 / 图形新算法优先级较低，核心模型和渲染来自外部。转向模型、渲染或仿真本身的研究；本库可作为交互层参考。
发布可靠的教学或产品应用还需要领域资产、资料、后端与验证。核验内容、错误与纠正流程、延迟和成本；当前示意没有证明学习收益或商业转化。

      
适合对象明确、动作有限、问答有帮助的场景。
课堂演示、设备培训、产品售前、展馆导览和研究内容检索都可以借鉴。基础 3D 展示本身已有其他项目可用；增加语音是否值得，应看访客能否更快找到对象、理解内容并完成任务。
投入包括场景和动画制作、领域资料整理、API 使用、服务器和数据接口维护，以及参数、错误和效果验证。本次没有量化这些成本，也没有证明语音一定比按钮方便。

      
接入你现有的 Pages 展示
前端可以继续用 Three.js。真实语音需要另外部署短期凭据接口、配置服务端 API Key，并处理调用预算、参数校验和执行反馈。本页无需密钥，构建后可直接放到编号子路径。

    


    

      
05 可扩展方向与验证路线
开发建议，尚未实现

      

        
优先 / 01
接通真实语音的小实验
选对象聚焦、动画播放、可信图表三个动作，接入短期凭据与 Realtime。用真实提问测试识别、延迟、打断和纠错，对比现有按钮入口。

        
优先 / 02
工具执行反馈与状态一致
加入参数验证、对象存在检查、动画完成或失败回报；遍历多个调用，处理顺序、取消、重复调用和超时，避免回答与画面不一致。

        
优先 / 03
可信资料与数据来源
接入教材、规格或结构化研究记录，让回答与图表显示来源、单位和更新时间；检索与引用组件需要新建。

        
迁移 / 04
通用场景操作适配器
把 focus、play、reset 等动作抽成明确接口，分别适配 Spline、Three.js 或普通网页组件。建立对象名称、别名与允许动作映射。

        
深化 / 05
真实数据驱动场景
给 ISS 加经纬度到三维坐标的映射，或将设备状态接到画面。加入刷新、插值和过期状态；仿真与诊断需独立模型和验证。

        
交付 / 06
运行记录与替代操作
保留按钮和文字入口，记录任务成功率、纠错次数、延迟分布与每次任务成本；补齐连接、麦克风、字幕和失败状态，并验证不同设备。

      

      
建议顺序
先在一个已有场景完成三个动作 → 核对执行与回答 → 接可信资料 → 测真实用户任务 → 再扩展对象、数据与场景。效果改善、教学收益和商业价值都以实验结果为依据。
