B / INPUT → WORKSPACE → OUTPUT

入口、输入和输出，分别是什么？

从人工操作到 Agent 接入，最终都落到同一套本地创作业务。

入口 / HOW

三种创作方式

  • 桌面界面：手动建立节点、导入素材、选模型、提交任务、编辑时间线。
  • 内置 Pi 助手：自然语言结合画布与媒体上下文，通过受控工具操作；付费媒体生成先提出方案，再由界面确认。
  • 外部 Agent：通过 MCP / CLI 接入已开放业务操作，使用客户端自身审批流程。
入口与权限合同 ↗
输入 / WHAT

意图、媒体与配置

  • 创意：主题、文案、镜头要求、提示词、风格与修订目标。
  • 参考：图片、视频、音频和已有结果；类型、数量、时长及上传方式受模型合同限制。
  • 执行：模型、渠道地址、密钥与参数；剪辑时输入时间线、字幕、音量和输出规格。
模型输入合同 ↗
输出 / RESULT

素材、成片与记录

  • 生成素材：文本、图片、视频、音频，具体类型由接入服务决定。
  • 最终作品：时间线渲染后可播放、可下载的视频。
  • 可继续修改的工作区：项目、节点、引用、素材、任务与会话记录。
  • 自动化反馈：任务状态、资源引用、操作回执；供后续检查与再操作。
工作区与任务持久化 ↗

文案或图片可以作为起点。 从它们走到最终视频，还需要选择模型、组织镜头、检查生成结果和编排时间线。自然语言能推动已开放的业务工具；精确动作和画面质量要由对应模型与后续编辑实现。

D / FROM INTENT TO EXECUTION

生成、助手和剪辑，各有执行链路。

工作台负责组织与执行；外部模型负责生成内容，FFmpeg 负责把编辑决定落实到成片。

01 / 生成链路

输入合同 → 任务 → 资产

  1. 读取提示词、模型参数与参考节点，检查类型、数量、时长和归属。
  2. Go 建立持久任务，适配器构造供应商请求；需要时先上传本地参考媒体。
  3. worker 创建与轮询异步任务，解析状态、下载结果并保存资源。
  4. 结果绑定节点，成为可预览、复用和继续剪辑的素材。

能控制模型选择、输入与受支持参数；无法据此保证人物一致、动作准确或文字无误。

模型合同与任务过程 ↗
02 / 助手链路

上下文 → 工具 → 再判断

  1. Pi 接收需求与画布、媒体上下文，管理模型对话与工具循环。
  2. 按只读、当前画布或完全访问范围，使用已经开放的业务工具。
  3. Go 校验身份、项目和版本，记录业务回合与操作，处理幂等、撤销与生成审批。
  4. 操作结果回到会话，助手检查并提出下一步，用户可继续修订。

新会话使用 Pi Durable 的 SQLite 持久化；已有 JSONL 由 Pi Coding Agent SessionManager 兼容。任务取消/重试等并非全部开放为助手工具。

Pi 与宿主职责 ↗
03 / 剪辑链路

时间线 → 语义计划 → 视频

  1. 时间线决定片段顺序、空隙、裁切起点、时长、音量、淡入淡出、字幕和输出宽高帧率。
  2. Go editing.Compile 编译统一剪辑计划，校验输入并保留内容语义。
  3. 原生执行器用 ffprobe 读取媒体事实，构建 FFmpeg filter_complex；浏览器降级由 wasm 执行计划。
  4. 任务完成后保存成片并关联画布，播放、下载或继续修改。

这是确定性剪辑能力；高级逐像素合成、自动精确口型与任意特效仍需新增实现或外部工具。

F / PRODUCT & ENGINEERING VALUE

价值来自过程连接与持续修改。

用户获得创作闭环，开发者获得可研究的职责划分；实际收益需要项目数据验证。

01

创作上下文可见

文案、参考、节点、任务和结果放在同一工作区，便于理解素材怎样进入作品。

适合多镜头与多版本比较，减少靠文件名和记忆维护关联。
02

生成与剪辑连通

生成结果回收到本地资产，接着进入编辑与导出，保留可修改过程。

价值落在从想法到交付的连续工作，而不仅是一次生成。
03

人工与助手协作

手动界面和业务工具共享对象，助手参与读取、组织、修订和执行。

用户可决定方向、批准生成并检查结果；工具开放范围需核对。
04

模型接入可替换

用目录、合同和协议适配隔离供应商差异。

利于模型比较和迁移；新渠道仍需真实任务及媒体合同验证。
05

资产与状态可追踪

本地存储保留资源、任务与会话，操作层维护版本、回执和幂等。

为排查、再编辑和自动化提供基础，不等于已完成企业审计系统。
06

工程机制可借鉴

Go 管业务语义、Pi 管助手循环、FFmpeg 管执行，接口有明确职责。

可复用在其他媒体工作台；本研究没有测量时间节省、ROI 或广告转化。

G / EXTENSION POINTS → PROPOSED WORK

有接入点，也有需要新建的能力。

以下是基于源码职责的扩展建议；验收条件说明怎样把设想变成可验证成果。

建议方向 01

行业模板与品牌约束

现有基础
现有画布、助手、选定 Skills 文件和业务操作。
需要补充
行业简报、镜头模板、品牌词汇、参考资产和检查规则；必要时新增工具。
验收目标
同一简报能形成可编辑草稿，人工确认品牌与事实，无需假设 Skill 可任意执行脚本。
建议方向 02

新模型与渠道

现有基础
模型目录、输入合同、协议 Adapter 与任务 worker。
需要补充
明确参考媒体类型/数量、传输方式、参数映射、轮询、取消和下载；管理供应商差异。
验收目标
至少验证真实创建 → 完成 → 下载和失败路径；模型 ID 可见不足以验收。
建议方向 03

更细的声音与剪辑

现有基础
统一时间线语义、FFmpeg 执行与已有媒体工具。
需要补充
字词级对齐、声音节奏、复杂转场/合成、更多输出规格；同时适配计划和执行器。
验收目标
素材时长、字幕时点、声画同步与两种执行路径一致性均能检查。
建议方向 04

质量评测与素材选择

现有基础
任务、资产、媒体检查、可追踪操作记录。
需要补充
固定样例、人工评分、失败分类、版本比较、成本和耗时统计、结果选择策略。
验收目标
把任务成功、可播放、符合要求分开衡量；用可重复样例报告效果。
建议方向 05

自动化工作流产品

现有基础
MCP / CLI 与受控业务工具目录。
需要补充
工作流编排、任务等待、重入恢复、运行记录与权限设计；补齐尚未开放的操作。
验收目标
能从输入走到成片，并在失败后可定位、恢复和核对副作用。
建议方向 06

团队与共享资产

现有基础
当前单用户、本地持久化工作区。
需要补充
同步/冲突协议、共享存储、身份和授权、资源归属、任务协调与访问审计。
验收目标
多用户并发、离线同步和资产权限可验证；这属于新增产品架构，非当前桌面默认功能。

图中的扩展与以上建议均不表示已经实现。评估二次开发，应同时考虑模型成本、本机渲染资源、媒体合同、数据持久化、操作权限和失败恢复。

使用前，确认这五个边界。

  • 本地工作区 ≠ 离线生成：提示词和相关参考媒体可能发送给供应商，生成可能收费。
  • 工作台控制 ≠ 模型保证：参数、镜头与时间线可修改；画质、人物一致性和动作准确度需逐项检查。
  • 工具可调用 ≠ 任意系统操作：助手受业务白名单和权限范围约束，不默认开放 shell、脚本安装或所有界面操作。
  • 候选版本 ≠ 已发行版本：固定提交的 VERSION 为 v1.7.14，但验收 JSON 的 releasePublished / releaseComplete 为 false。
  • 性能优化 ≠ 端到端证明：空间索引与内存操作测试可见；没有据此验证 5 万节点流畅创作、全平台稳定性或商业收益。

为什么旧文档说“内置 Agent 已退场”？＋
