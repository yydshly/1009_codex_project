# 新疆三维知识平台阶段总结与后续设计

2026年10月14日。当前三维运行版本停在 R90，作为可操作的探索原型保留；本次归档整理反思和后续设计依据。下一阶段从真实事件与多尺度地图开始设计，已有模型、交互、声音和素材作为可复用基础。

## 阶段成果与适用范围

当前已经连通地球定位、新疆全域认识、历史事件、地点模型和返回地图。保留自由旋转与缩放、参数与选择、暂停与接管、探索记录恢复。张骞出使、西域都护、锡伯西迁及一号冰川共有四个导演主题、52幕，已配置讲解和字幕。其他自然、文化、家庭、庭院、关口和工程场景继续可操作；它们没有全部建设独立导演或同等深度的故事。

这些成果证明了入口、对象联动和观看控制可以共用一个平台。知识覆盖仍是选取的案例，人物与建筑多为解释模型，尚未形成覆盖新疆各区域和各时代的完整知识产品。功能检查通过表示相应行为符合检查条件，不能替代内容完整性、历史考证和用户体验验收。

| 内容维度 | 已有基础 | 后续需要补足 |
| --- | --- | --- |
| 自然与地理 | 地球、区域地形、山地盆地、水系、局部冰川影像和高程 | 区域细图、县域或聚落地图、地点与周边环境的连续关系 |
| 历史 | 八段年代索引及三条较深入的历史路径 | 有出处的具体节点、时间关系、事件过程及影响延续 |
| 文化与民族 | 传习、家庭、迁徙与部分传统形制资料 | 对具体社区、时期、地方差异的材料，人物身份与活动依据 |
| 经济 | 交换、补给、生产和关口协作情境 | 对应时期的货物流向、生活需求、生产条件及可核查案例 |
| 政治与治理 | 机构、迁徙与安置背景 | 制度如何通过具体地点、组织与行动影响地方生活 |

## 探索中暴露的问题

### 产品目标曾偏向制作影片

连续镜头和完整成片一度成为主要成果，用户主动认识地点、切换问题、观察变化的结构建设滞后。后续以可控制的三维知识平台为目标：自动导演演示同一套可操作对象，录像用于保存使用过程。

### 宏观地图承担了过多解释

地理、事件、地点和人物长期压在同一个区域模型上。一个标记配一段讲解能建立概念，却难以说明山口、河流、绿洲与行动之间的具体关系。人物场景独立出现后，用户也容易失去它与周边空间的联系。

需要补齐区域、县域或历史聚落、具体地点这些中间尺度。地图细化的目的，是让用户看清事件发生的位置和过程；更高分辨率的纹理只有在支持这些观察时才产生实际价值。

### 故事有起讫和结论，中间过程仍薄

“背景、过程、影响”已经形成结构，但实际过程仍有较多概括。一个事件应进一步拆成能定位、能观察、有时间关系的节点，解释行动目的、当时条件、发生的变化及后续结果。宏观联系线和通用人物动作不能独自承担这些内容。

### 局部精修先于整体设计

人物小动作、字幕、标签、镜头和声音逐轮增加，入口与介绍也曾重复。局部质量提升没有自动形成清楚的知识路径。下一阶段先确认故事、空间层级和交互顺序，再选择必要的模型与表现效果；新增动作必须对应一个需要理解的事件或机制。

### 史实、现代参照与示意场景需要持续区分

张骞记载的出使经历与后来的长期交流不是同一段行程；现有喀什集市是跨时期交换情境。现代轮台定位与乌垒研究不能直接等同，抽象建筑不表示考古测绘布局。锡伯迁徙、安置和后期水利应按不同时间段呈现。冰川真实地表观察与教学流向、无单位收支试验分别标注。

这些边界已有页面与资料记录，应作为后续内容设计约束继续保留。史料无法确认的具体道路、人物言行和建筑布局，不因制作动画而获得事实身份。

## 多尺度地图设计

后续探索顺序为：**地球 → 新疆全域 → 区域或河谷 → 县域或历史聚落 → 具体地点 → 人物行动**。六个尺度是设计目标，当前运行时尚未完整实现。

| 尺度 | 用户要理解什么 | 对应画面与操作 |
| --- | --- | --- |
| 地球 | 新疆在世界、中国与周边的位置 | 大陆和国家名称分层，新疆范围清晰，主动定位和进入 |
| 新疆全域 | 山脉、盆地、水系与主要通道的整体关系 | 保持完整地理背景，选主题、区域或事件，再进入下一层 |
| 区域或河谷 | 为什么故事发生在这里，地理如何约束行动 | 展开山口、河谷、绿洲和补给地点，对比可确认的空间关系 |
| 县域或历史聚落 | 从哪里进入、在哪停留、地点之间如何联系 | 显示适用年代的聚落和活动节点，观察到达、停留与转移 |
| 具体地点 | 事件发生在什么设施或生活空间 | 显示有依据的建筑、院落、田地或工作空间，对象可点选 |
| 人物行动 | 谁在什么条件下做了什么，产生什么结果 | 行走、停留、交流、作业及回应与事件进程同步 |

只对故事涉及的关键区域逐层展开。一个事件不必使用全部尺度，但应交代省略的空间关系。历史区域、古地名与现代县界分别显示；现代边界用于定位时注明参照年代。不能默认当代县城就是历史事件的聚落位置。

进入下一层前，画面说明当前问题、目标地点和进入理由。进入后保留上层位置提示；返回恢复主题、地点、进度和视角。地图与模型共用地点身份和空间参照，用户能看到模型在区域中的位置，而不是只看到突然出现的独立模型。

## 真实故事的节点组织

先完成资料梳理，再写导演脚本和制作人物动作。每个节点至少记录以下内容，缺少依据的字段保留未知或明确示意。

| 字段 | 需要描述的内容 |
| --- | --- |
| 时间 | 日期或时期、前后顺序、确定程度，区别于动画播放秒数 |
| 地点 | 点、范围或地域参照，关联上层地图及适用尺度 |
| 参与者 | 可确认的身份与角色；匿名人物表示活动，不冒充具体史实人物 |
| 行动及原因 | 行动目的、环境条件、组织安排，以及资料支持的因果关系 |
| 起点与目的地 | 地点间如何移动，哪些路线能确认，哪些只表达方向 |
| 过程与结果 | 到达、停留、交接、建设或使用如何改变后续状态 |
| 画面对应 | 哪个地点高亮、哪条路线变化、哪个对象或人物产生动作 |
| 资料依据 | 来源、采用段落或页码、日期、表示范围及素材许可 |
| 用户操作 | 暂停、回看、比较、点选、自由观察和返回后的保留状态 |

行走应呈现起点、目的地、停留原因和结果。史料只能支持地域联系时，使用方向或范围示意；资料支持具体路段后，再呈现贴合真实地形的行进。人物回应表达资料支持的活动结果；原创对白和假设选择明确属于解释情境。

自然、地理、历史、文化、民族、经济和政治通过这些节点交叉呈现。某地的服饰不能代表全部人群，地形也不能单独推出制度或文化。每个节点只呈现有内容与依据的维度。

四个已保存入口和四个导演不等于内容覆盖全面。后续用“问题、资料、地点、画面变化、用户操作”检查各主题，明确哪些已有、哪些待研究、哪些只作情境实验。

## 下一阶段的开发顺序与验收

1. **先整理证据和故事节点。** 为候选事件建立时间、地点、行动与来源表，确认可做的细化范围。
2. **再选择一个资料较完整的区域样板。** 用已有资料评估选题，完成全域到区域、聚落、地点的尺度设计和粗略可操作地图。
3. **接通事件过程与空间。** 地点、路线、对象状态和人物行动读取同一节点进程，完成进入、停留、转移与返回。
4. **完善必要的画面和声音。** 根据观察距离安排地形与环境细节，依据年代制作人物与建筑，讲解、字幕和动作同步。
5. **按同一标准检查其他线索。** 保留自由探索和现有导演，逐条补足证据与空间，不以新增幕数作为完成指标。

样板验收应观察：用户能否指出当前地点及其周边，能否说明进入下一层的理由，静音能否读懂行动与结果，返回能否保持来路，导演暂停与自由接管是否稳定，历史陈述是否能回到具体来源。数据缺失的地点保持相应精度，不通过放大宏观纹理宣称已完成聚落细图。

## 阶段保存与继续开发

R90 是运行能力基线，R91 是本次归档与反思记录。已有冻结轮次和共享对象保持只读；后续编辑实时 `web/` 或恢复后的独立副本，按 `process_store.py save` 保存增量。截图、影片、声音母片、候选版本、源码与校验记录继续保留，同一内容只保存一次。

Git 阶段提交保留当前源码、运行素材、设计反思和逐轮清单；完整的历史过程材料与大体积影片保留在本机共享素材库。迁移到其他机器时，还需备份共享对象库和清单，或按需要导出独立交付包。浏览器“我的探索”保存在用户本机，继续使用前可从平台导出配置；源码归档不自动代替个人记录备份。

后续接手先阅读本总结，再查看当前运行说明和证据。旧蓝图、旧影片及未采用版本是研究过程，不代表最新实现或后续需求全部完成。
