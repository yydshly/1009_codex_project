# R51 · 绿洲水路的可控观察与地点比较

2026-10-13。延续最终产品方向，做可操作3D网页。本轮没有新增影片、配音或遥测资产，旧原片、历史演示、33条旁白与19条人物声音继续共享。

## 实现

从地球交流主题，经全域通道和秦汉事件，先进入吐鲁番比较停留的用水条件。水路以取水、竖井、暗渠、出口/蓄水四处结构引导观察，竖井增加清理装置、维护者与淤积；下游增加空腔池壁、显示水位、固定作物细节和取水者。来水不变时可比较通畅、淤积与清理，输出滞后变化而非马上同步改三个刻度。动画和显示强度是原创教学，不含实测单位、年代或产量预测。

稳定后可记录条件与结果，最多保留本次页面的四种对照，重复同条件更新一行。模型返回保留条件、响应、对照和暂停状态。URL保存供水、通畅/淤积条件和结构选点，不恢复维护动画的精确时钟或本次对照表。

接入已有地面用水选择，再返回地图定位喀什、参与物品交换；可以反向比较用水。两个独立地点比较同一问题，不表示同一水路、同一商队或真实货物传播；两套水路/用水场景比较机制，不把试验刻度换算成供水量。历史到工程是跨时期延伸，不把坎儿井的某个年代归于出使。普通旧水路和影片不启用新增观察层。

## 实际验证与修正

Earth→通道地图→秦汉背景/过程/影响→吐鲁番定位→水路走通。背景/过程/影响选择对应原事件对象，新的默认地点先接水路，原喀什自由入口仍保留。

route-return-before/after.json记录经过绿洲、地图与集市后返回：obstruction、outlet、reservoir、care、stop和simulation=paused相同，三条对照文字相同。通畅来水65/下游65；淤积65/12；清理后65/65，为作者定义的显示值。oasis-response.json中waterHome=1、waterReply=responded；market-response.json中织物0、交接完成，物品使用与家人回应。纯逻辑检查验证条件变化的延迟、零来水、清理、冻结、恢复和结构点。

pause-before/after.json确认暂停期间模拟时间、淤积、下游状态和镜头不变。reduced-early/final.json补充供水降到20的渐变与结果，属于候选检查记录；最终主路线对照每次保持供水65。

首次等待稳定超时，下一次读取已经稳定，保留实际数据，没有重做选择。另一次全景后等待响应失败，发现旧导航重选场景导致暂停、时间归零及周边隐藏，已改为只调整相机；结构定位也直接改变相机，最终路径定位后simulation仍running，周边仍显示。组合等待模型转场曾返回失败但诊断已经有可见匹配，随后直接读取settled状态和实际画面继续，没有把等候失败计为通过。

01—03是候选：初期人物双臂姿态、植被、实心池与低水位显示；02为初期近景。04—07包含修正后的水位、通道、清理和地面选择检查。08—11是地球/地图/事件/地点；12—15为完整主路线的通畅、淤积、清理与对照；16—18是用水回应、地图重新定位和交换；19为对照可读视图，20为390×844窄屏，其余桌面1280×720，尺寸差别不作同像素质量比较。最后补充最终版本截图及汇总页。截图均为实际浏览器画面，不是生成图或历史复原。
