## 当前代码真正承接了什么

`web/public/journey-memory.js`的`carryFor`确实承接前幕观察：先到家里推荐集市织物，先到田里推荐补给；集市织物推荐家庭先安顿，其他货物推荐先引水；家庭工具推荐直接参与庭院，家书推荐先观察。`lived-scenes.js`读取它排序并选择默认分支。因此不能说“完全没有关联”。

但这些是关注点与默认分支的映射，不是前幕变化产生后幕必要条件。`carryFor('logistics')`读取的是`ledger.market`，没有读取`ledger.culture`，是庭院到关口断裂的具体依据。`story-thread.js`也明确将集市、历史家庭、庭院和当代情境定义为不同案例的比较，不能把此图理解为真实家庭或物件的连续经历。

`journey.js`中的三处过渡分别使用“从商旅，转向一次有年代的远行”“先看区域，再走进另一个社区”“回到整体，看当代的三个节点”。它们说明了切换，但没有充分说明观众为什么需要此时切换。`modern-kashgar`实际标题与地点是霍尔果斯；这是历史代码命名遗留，单凭内部ID不能判定画面误定位。

## 优先修正方向

1. 用一个贯穿的观众问题组织空间主线：**这片土地如何让人停留、生活，并与外界建立联系？** 地球—新疆—水路与聚落—绿洲节点—交换与通行—公共取舍—回到地图。主线传递观察问题，不伪造冰川到吐鲁番的实测水系。
2. 历史与文化作为地图上明确进入、明确返回的案例。进入西迁前提出“人的移动有哪些不同原因、抵达后怎样安顿”；进入庭院前提出“生活记忆怎样由具体社区接续”。案例有自己的年代、人物与依据，不用一句过渡把它们伪装成连续事件。
3. 每次离开场景都留下可核对的后果或未解问题；下一处先呈现为何需要比较它，再开始人物动作。跨幕记录应是看得见的观察线索，避免把前一社区的事件直接算成另一社区的变化。
4. 结尾先回看选择带来的实际变化和仍未满足的需求，再回到地球。七个领域围绕这些问题参与解释，不以逐个出场作为融合的验收标准。

本轮不把新的镜头平滑或更多连接字幕当作结构问题的验收依据。重排段落与交互问题后，才能确定应修改的动画、镜头和旁白。

## 可访问性风险与审查限制

时间标签可以通过按钮定位，视频可由键盘暂停与前后定位，这些操作本轮实际使用。并排观看时，影片字幕、人物标记、地图和选择面板同时缩小，需要反复转移视线；固定影片里的文字不是可选择的文本，也无法由当前截图证明读屏支持或WCAG合规。重做主线时应减少同屏任务，并给信息留出阅读时间。

本轮结合实屏与当前源码作结构判断，未进行用户测试或完整的多分支观看实验，未重新听审整条声音，也未以静帧证明全部动态镜头质量。判断侧重段落顺序、切换动机、可见人物关系与选择承接。R25技术声画同步通过不等于叙事已完成。

七个整屏截图、联络图、代码摘取依据和本轮源文件按R25基线增量保存；影片直接复用既有资产。原页暂停状态与观看位置保持不变。
