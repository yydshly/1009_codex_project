## 风格怎样渲染

### 造型与配色

`palette.js` 提供纸色高光、蓝绿色阴影、建筑与植被用色。世界使用简化而有明确轮廓的几何；`world/index.js` 注释说明每个物件的位置是为了起始镜头构图。因此“程序化建模”指用函数生成部件，场景的审美和布局仍由作者设计。

### 分档光照与阴影偏色

`toon.js` 创建 `MeshToonMaterial`，用 `DataTexture` 作为 gradient map。三档强度为 `[92, 178, 255]`，最近邻采样并禁用 mipmap。不同法线方向得到较整齐的明暗色块。浅色树冠等物件使用 `soft/soft3` 高亮色带。

`onBeforeCompile` 替换 toon 光照片段，用 `uShadowTint` 给较暗档位混入冷色。这依赖 Three.js ShaderChunk 中的具体字符串；本地固定 Three.js 版本，升级时应重新检查补丁兼容性。

依据：[toon.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/core/toon.js)、[palette.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/core/palette.js)。

### 从深度图提取轮廓

`post.js` 将场景渲染为颜色纹理与深度纹理，线性化深度后，计算中心和上下左右像素的二阶差分，例如：

```text
sx = (depthLeft + depthRight - 2 × depthCenter) / depthCenter
```

凸起和轮廓使用较强线条，凹角较轻；远处衰减，天空不描边。这能避免仅按深度一阶梯度描线时，在倾斜平面上到处出线；它并不检测任意材质色块边界。

电车等重要物件另用 `outline.js` 的背面外壳，以投影空间顶点偏移获得外轮廓。网页“描边强度”主要控制深度描边，并在零值时隐藏外壳，不连续改变所有外壳线宽。

### 调色和抗锯齿

颜色/深度 → ink pass → grade pass → FXAA → 屏幕。grade 按亮度混合冷影与暖光，控制暖度、饱和度、暗部抬升、暗角，同时负责 linear → sRGB 输出。雾在场景材质渲染阶段处理，不是独立后处理 pass。

本地原色对照换用 256 级连续 ramp，关闭描边和雾，采用中性 grade 并保留 sRGB 转换。它仍使用 toon 材质和简化模型，不是 PBR 写实模式。

依据：[post.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/core/post.js)、[outline.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/core/outline.js)。

场景的模型与纹理由代码生成，没有依赖预制 glTF。六张网页样例是上游截图，只作为记录和参考，没有代替实际 3D 几何。

参数重复降低创建成本，种子令局部差异可复现，物件坐标和叙事内容仍需要明确设计。静态几何按材质及阴影设置合并；树冠用 `InstancedMesh`。合并后修改单个静态部件通常需要重建批次，不能把每个部件都视为独立可拖拽物件。

### 球面投影

`R=150`，球心 `C=(0,-R,0)`，`x/R` 是经度，`z/R` 是纬度，局部高度为 y：

```text
P = C + (R + y) × (sin(x/R)cos(z/R), cos(x/R)cos(z/R), sin(z/R))
```

普通几何细分长边后弯曲；实例和动画组用球面切线坐标变换，动画在局部坐标继续运行。玩家的碰撞/高度查询保留在平面 XZ，相机显示为球面位置和方向。电车沿赤道运行，X 按圆周包装，环线能连续闭合。

依据：[planet.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/world/planet.js)、[player.js](https://github.com/amirmushichge/dvor/blob/30d6f684670915865743c79f44f931a43d987113/src/core/player.js)。

## 本地场景：第一次到访社区

任务链：识别入口 → 看当天活动 → 找到书屋 → 在树荫下休息。

`community.js` 复用 Batch、材质、球面、树木、长椅和设施，新增入口、公告板、书屋、书脊、步道、围栏、住宅。`content.js` 关联四个地点的坐标、镜头、中英文内容。

路线或三维标记点击 → 相机定位 → 展示说明 → 进度更新。实际公告平面点击 → Raycaster 命中 → 对应 note → 英文解读。漫游使用上游 Player，动画按钮调用实际转盘交互。

“柳荫里”、开放时间和活动均为演示数据，不代表真实场地。真实产品要以经确认的测绘/平面图替换坐标，由信息维护者提供活动、开放时间和通行条件。

| 控制目标 | 网页操作 | 后续改造入口 |

## 不参考原作的提示词控制

新增网页 `#prompts`，整理的是本次讨论中的创作方法，属于方法建议，不是上游能力或已经运行生成的新作品。

把风格写成七项可执行规格：造型、构图、配色、明暗、灯光、描边、氛围。编程模型需要实现几何、实时材质与控制面板，图像模型重点确定一张画面的构图和艺术方向。可控的生成流程先做最小场景，固定镜头与种子，以截图校准视觉，再扩展物件和交互。

完整模板在 [prompt-guide.js](web/src/prompt-guide.js)，网页提供可编辑文本、模板切换、复制、TXT 下载与初始内容恢复。模板切换保留本次编辑，刷新会恢复默认模板，长期保存应下载文本。复制被浏览器限制时，显示手动选中文本，避免声称复制成功。

“带入当前实验参数”读取 `window.__dvorLab.style`，追加可审阅的参数参考，保留自定义正文，重复带入替换旧参数块。只采集风格配置，镜头、原色对照与动效不在其中。雾近远距离采用本页映射公式；描边百分比、暖度和场景单位在独立工程中仍需重新标定，不能视为跨渲染器的统一标准。

四个可复制的修正示例覆盖阴影过黑、轮廓过密、树冠零碎、表面细节过多。每个示例按“保留条件 → 当前问题 → 单项修改 → 同镜头截图”组织。文字规定方向，实际输出和截图决定是否需要继续校准。

新增验证见 [prompt-verification.json](assets/prompt-verification.json)：七项通过，错误和失败请求均为 0。检查实际剪贴板与 TXT 内容、编辑保留、实验数据带入且不改变场景、四条修正复制、失败回退与 1024/768/390/320px 布局。Windows 剪贴板的 CRLF 换行在断言时规范化，下载文件仍按 UTF-8 原文验证；这不构成对模型生成质量的验证。

## 使用场景和扩展方向

以下是推导和建议，并非上游已有产品功能：

- **文化展览 / 城市记忆**：以地点组织口述史；扩展史料来源、编辑审核、多语言、直接阅读的列表入口。
- **社区 / 校园导览**：服务信息绑定真实位置；扩展真实平面数据、查询、无障碍路线、触屏导航和内容更新。
- **语言学习 / 叙事**：标牌阅读变成练习或故事；扩展语音、任务状态、进度保存。
- **风格原型**：换模型保留管线；扩展 glTF 导入、材质适配规则与配置工具。
- **工程化**：布局数据化、场景编辑、资源释放、LOD、分区加载、性能分档、真实手机实测、WebGL 回退。

先补信息和设备入口，再扩大世界。球面小行星的艺术表现与真实导航的准确性需要分开评估。
