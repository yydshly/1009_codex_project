02 / HOW IT WORKS

手绘感，是一套可控制的规则。

造型提供轮廓，材质形成色块，灯光建立冷暖关系，后处理统一画面。它们共同决定风格。

  1. 01几何与场景材质Canvas 纹理 / 色带
    灯光、阴影偏色与雾
  2. 02颜色 + 深度两类离屏纹理
    随相机实时更新
  3. 03轮廓提取深度二阶差分
    重要物件另有外壳
  4. 04冷暖调色饱和度 / 暗角
    linear → sRGB
  5. 05输出画面FXAA 抗锯齿
    按像素预算采样

雾在场景材质渲染时处理，后期依次为 ink → grade → FXAA。原色对照仍采用 toon 材质与简化模型，不能视为 PBR 写实模式。

连续的光照，如何变成整块明暗？ +

MeshToonMaterial 查询一张很小的光照纹理。三档色带值为 92 / 178 / 255，采用最近邻采样，档位边界更清楚；着色器再让较暗档位混入蓝绿色。树冠使用较亮的柔和色带，避免暗面过重。

依据：toon.js ↗
描边为何能随 3D 视角变化？ +

深度图随摄像机实时生成。后处理计算中心与邻近像素的深度二阶差分，突出轮廓与折角；远处的线逐渐淡出。电车车身另加背面外壳，用投影空间偏移形成更明显的外轮廓。

依据：post.js / outline.js ↗
整个世界怎样由代码搭建？ +

先用盒体、圆柱、管道和贴图平面生成物件，再用参数化函数重复窗户、阳台和树冠。种子控制细节变化，物件位置由作者布置。静态几何按材质合并，重复树冠用实例绘制；标识由 Canvas2D 在加载时画出。

依据：kit.js / buildings.js / textures.js ↗
为什么庭院能变成一颗小行星？ +

场景在平面 XZ 坐标中制作，随后映射到半径 150 个场景单位的球面：x / R 对应经度，z / R 对应纬度。普通几何细分长边后弯曲，实例与动画组整体搬到球面。行走碰撞仍在平面计算，摄像机按球面位置与切线坐标显示。

依据：planet.js ↗

WORLD CONTRACT / 世界与运行数据

程序化部件，组成作者设计的空间。

原作的模型和纹理由代码创建，核心世界不依赖预制 glTF。参数减少重复劳动，种子固定局部差异；布局、起始镜头和生活故事由作者明确编排。

  1. 基础积木盒体、圆柱、曲线与标牌平面
  2. 参数化部件窗户重复、树冠团块与 Canvas 字样
  3. 人工布局入口、步道、住宅、树木和镜头
  4. 运行契约碰撞体、高度面、热点、更新回调
  5. 球面显示几何弯曲，动画组沿球面切线运动

显示坐标与行走查询如何配合？

以 R = 150 个场景单位、球心 C = (0, −R, 0) 映射物件；x / R 与 z / R 对应经纬度。普通几何先细分长边，实例和动画组使用切线坐标变换。碰撞与高度仍在平面 XZ 查询，相机呈现球面位置与朝向，电车环线可连续闭合。

哪些变化只需参数，哪些需要重新建造？

色带、阴影、光源、雾和调色可以实时修改。改变建筑、树木与路线位置要更新几何与相关运行数据；静态合批以后通常需重建。网页只保存风格，不保存布局，也未提供拖拽建模编辑器。

查看球面映射与深度描边的简化表达
P = C + (R + y) × (sin(x/R)cos(z/R), cos(x/R)cos(z/R), sin(z/R))
sx = (depthLeft + depthRight − 2 × depthCenter) / depthCenter

第一行把平面局部坐标映射到球面；第二行是一个方向的归一化深度二阶差分，配合纵向、阈值和距离衰减形成轮廓。两者对应不同层次，不能混为一种特效。

VALUE / 为什么值得研究

把氛围、结构与内容变成可修改的规则。

它的价值来自具体实现与创作方法。我们可借此理解风格的组成、验证复用，并决定哪些机制适合自己的任务；现有实验未证明商业转化或量化效率提升。

对学习者

看清风格的因果关系

同一几何与镜头下调色带、阴影、太阳和描边，将“更像动画”拆成可讨论、可截图比较的条件。

对创作者

复用稳定规则，重做表达

材质和管线统一新物件的观感；参数化积木支持重复结构。造型轮廓、构图与叙事仍需要自己的设计。

对产品与内容团队

把位置和说明放在一起

导览让访客从入口走到服务点，文化注释把涂鸦变成可读故事。是否改善任务完成，需要真实用户与场地验证。

对我们的研究总库

保留一个可验证的迁移样本

固定源代码、版权、真实截图与运行结果；社区实验验证了模块接入，提示词工具把经验带到独立工程。

如何选择投入方式？

学习渲染时，先保留小场景与固定镜头；做文化体验时，先组织地点和故事；做真实导览时，先确认平面、通行与更新责任。若任务以查询为主，应保留直接阅读列表；三维展示服务于信息获取和空间理解。

06 / PROMPTING THE STYLE

不参考这个库，怎样用提示词创作？

把造型、构图、材质、光照和镜头写成可执行的视觉规格，再用实际截图逐轮校准。下面整理的是独立创作方法与提示词模板。

编程模型

生成可交互的 3D 网页

要求模型实现几何、材质、光照和控制面板。效果在浏览器中实时产生，之后可以继续调参数、扩展世界。

图像模型

先确定一张画面的艺术方向

重点描述构图、形体、色彩和光影。生成的图片可用作视觉参考，再把这些规则落实到实时 3D 工程。

把“画风”拆成七项规格。

每项同时写清要求和观察方法，方便判断下一轮该改哪里。

控制项写入提示词的要求怎样校准
造型房屋用简化体块；树冠用少量团块；窗户和阳台重复排列。先看整体轮廓，再决定细节数量。
构图从入口看向内部；设施形成视觉中心；树木围合两侧。固定初始镜头，比较主体是否清楚。

01 / 阴影过黑

提高可读性，保留体积。

保持模型、布局和镜头不变。当前暗部太黑：提高暗部亮度，让阴影偏蓝绿色，保留地面投影与建筑体积感。修改后提供同一镜头截图。

02 / 轮廓过密

收敛内部细节的线条。

保持灯光和配色不变。当前轮廓线过密：减少建筑内部细节的描边，保留建筑外轮廓和主要结构线，远处线条进一步减弱。修改后提供同一镜头截图。

03 / 树冠零碎

先整理主要形体。

保持渲染规则不变。当前树木显得零碎：减少树冠团块数量，增大主要体块，让树冠整体轮廓更明确，再添加少量局部变化。修改后提供同一镜头截图。

04 / 表面细节过多

让画面回到大块色彩。

保持物件数量、布局和镜头不变。当前表面细节过多：减少细碎纹理和高光反射，使用整块基础颜色与三档明暗。保留主要结构和生活标识，再用同一镜头截图检查。

怎样判断模型交付完成？

  • 主体轮廓清楚，大块明暗与冷暖关系符合规格。
  • 固定镜头、布局和种子，修改前后能直接对照。
  • 3D 工程中的参数实际改变画面，交互能够操作。
  • 提供实际运行截图和测试结果，再扩展新物件。

文字设定方向，截图校准结果。有参考图时，把图和视觉规格一起提供给模型。这里的模板是方法建议；本页现有 3D 实验的代码来源见实验说明。

01 / 内容与设备入口

把演示变成可信导览

验收：现场位置对应、信息可更新、访客能完成任务；在真实手机与受限设备测试。
02 / 配置与编辑

让不同创作者复用同一套规则

布局与内容数据化，建立场景配置、参数导入和编辑工具；按许可接入 glTF，适配材质、尺度、碰撞与语义热点。

验收：新场景可保存和恢复，修改不破坏导览、动画或版权；合批资源能够重建与释放。
03 / 叙事与工程化

有选择地增加故事和规模

扩展语音、练习、任务状态与进度保存；按需要增加 LOD、分区加载、质量分档和 WebGL 替代视图。

验收：先明确任务与设备预算，再测响应、显存和可读性；球面艺术效果与真实导航准确性分别评估。
